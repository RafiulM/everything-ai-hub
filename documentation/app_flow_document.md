# everything-ai-hub App Flow Document

## Onboarding and Sign-In/Sign-Up
A new visitor lands on the Everything AI homepage by navigating to the application URL. The homepage displays a brief introduction to the AI services and presents clearly labeled buttons for creating an account or signing in. When the user chooses to sign up, they are taken to a registration form that asks for an email address and a password. Upon submitting valid information, the system securely stores the credentials via Better Auth and automatically logs the user in. If the user already has an account, they select the sign-in link, enter their email and password on the login form, and submit to access the application. For users who forget their password, a “Forgot Password” link on the login page opens a form requesting their email. After submitting, they receive an email with a secure link to reset their password. Once the password is reset, they return to the login form and can sign in with their new credentials. Every authenticated page includes a sign-out option in the header that ends the session and returns the user to the homepage.

## Main Dashboard or Home Page
After signing in, the user is redirected to the main dashboard at the `/dashboard` route. The dashboard features a persistent sidebar on the left that lists all major sections: Chat, Image Generation, Web Scraper, Analytics, and Settings. At the top of the page, a header displays the user’s name and a sign-out button. In the center of the dashboard, dynamic widgets show recent activity, usage charts, and tables summarizing AI service consumption. From this view, the user can click any sidebar item to navigate to the corresponding feature pages. The sidebar remains visible as the user moves through the app, ensuring that navigation options are always accessible.

## Detailed Feature Flows and Page Transitions
When the user clicks on Chat, the app navigates to `/chat`. On this page, the chat-interface component appears. It shows the conversation history at the top and an input field at the bottom. As the user types a message and presses send, a Server Action reads the user’s stored API key, calls the Vercel AI SDK, and streams the response back into the chat window in real time. Each exchange is saved to the database as a chat_message record. After sending, the user can continue the conversation or switch to another feature by clicking the sidebar.

Clicking Image Generation sends the user to `/image-generation`. Here a form lets the user describe an image prompt. Upon submission, a secure API route calls the chosen image generation model, stores the prompt and resulting image URL in the database, and then displays the image on the page. Users can adjust prompts and generate multiple variations, with every request logged for analytics.

Selecting Web Scraper leads to `/web-scraper`, where the user enters a target URL and selects scraping options. Submitting the form triggers a Next.js API route that integrates with Firecrawl to retrieve structured data. The returned data is shown in a results panel. All scraping jobs and their statuses are recorded for later review.

When the user returns to the Analytics section on the dashboard, live charts and tables update to reflect usage across all features. Server Actions fetch summarized data from the usage_analytics table, grouping token counts by model or service type. The chart component renders these statistics, while the data table lists individual usage records. The user can filter dates or service names to focus on specific activity.

## Settings and Account Management
The Settings page at `/settings` lets the user manage personal information and API keys. In the profile section, the user can update their display name and email address, then click save to persist changes. In the API Key Manager section, the user sees a list of stored third-party keys, each encrypted in the database. They can click an “Add Key” button to open a form where they enter a service name and the raw key. Submitting stores the encrypted key. Keys can be edited or deleted, and changes immediately take effect. After modifying settings, the user can click “Back to Dashboard” or use the sidebar to resume using AI features.

## Error States and Alternate Paths
If a user enters invalid data during sign-up or sign-in, the form displays a clear message next to the offending field, and the page prevents submission until the error is fixed. During password reset, expired or invalid links render a page explaining the issue and offering to resend the reset email. If the user loses internet connectivity while using a feature, the app shows a full-screen offline message and automatically retries requests when the connection returns. For restricted actions, such as accessing a protected route when not logged in, the user is redirected to the sign-in page with a message that authentication is required. If an AI service call fails due to network errors or API limits, the feature page surfaces a toaster notification explaining the problem and suggests retrying later.

## Conclusion and Overall App Journey
From the moment a user discovers the Everything AI hub and creates an account, they move seamlessly into a protected environment where they can access a unified suite of AI services. Signing in leads them to a central dashboard that connects to chat, image generation, and web scraping features. Each feature uses secure server-side calls and persists results for real-time analytics. Users can manage their profile and API keys in a dedicated settings area and return to the dashboard at any time. Throughout the experience, clear feedback guides users around errors or connectivity issues, ensuring they can focus on generating AI content and tracking usage without friction.
